# Credits

## Floor plans

The indoor plans under "Getting there" are generated by
`scripts/fetch-indoor-maps.mjs` from **© OpenStreetMap contributors**, whose
data is available under the [Open Database License](https://opendatacommons.org/licenses/odbl/).
Each plan links back to the OSM element it was drawn from, which is how the
ODbL attribution requirement is met on the page rather than only here.

The plans are a derived rendering: indoor room, corridor and wall geometry on
the lounge's level, rotated so the concourse runs horizontally, cropped around
the lounge, with `aeroway=gate` references labelled.

102 of 330 lounges have one. Coverage depends entirely on whether someone has
mapped that terminal's interior, so the rest show no plan at all. Two rules
keep the bad ones out:

- **A plan must say something.** Either the rooms around the lounge are drawn,
  or at least four gates near it are labelled. ATL's Concourse B has almost no
  rooms mapped, but "between B18 and B20, with B6 to B29 running past" is
  exactly how the airport signposts itself. A lounge with neither is a marker
  floating in an empty frame, and gets nothing.
- **A plan must be the right room.** An OSM point is only paired with a lounge
  when the gate references around it agree with the concourse our data names.
  ORD has five United Clubs; brand-and-airport matching alone paired the
  Concourse C one with a Concourse B point, which would have sent people to
  the wrong pier. Unconfirmed pairings are dropped — 15 of them, against 102
  kept. Run with `DEBUG_MATCH=1` to see each decision.

What this is not is turn-by-turn routing. That needs a walkable indoor graph,
which OSM does not have for these terminals. The map will show you where you
are and where the lounge is relative to the gate numbers; it will not tell you
to turn left.

### Interactive maps

`scripts/build-airport-map.mjs <lounge-id>` goes further for a single lounge:
it emits `public/maps/<id>.json` with the *whole* airport — every concourse and
terminal outline, the people mover, all gates, and indoor detail on every
mapped level — and flags the lounge `interactive` in the manifest. The page
then renders `AirportMap`, a pan-and-zoom map that layers detail in as you zoom
and can place you on it from `navigator.geolocation`.

Two things that were subtly wrong and are worth not re-introducing:

- **Rotation must come from the lounge's own concourse, not the airport.** At
  ATL seven parallel piers form a blob whose principal axis runs *across* them,
  which stood Concourse T on its end.
- **The smallest containing polygon wins.** The lounge sits inside both
  "Concourse T" and the enclosing "Domestic Terminal"; picking the first match
  gives the wrong home and the wrong default view.

Payload for ATL is 35KB, fetched on mount rather than bundled.

## Why only thirteen

Because that is how many exist. Photographs of specific US airport lounges
under a license that permits redistribution are genuinely scarce:

- Airline and card-issuer press photos are copyrighted, however freely they are
  handed out. A press kit is not a license.
- Review sites, blogs and forums hold thousands of lounge photos, essentially
  all of them all-rights-reserved.
- Wikimedia Commons is the one large free pool, and
  `scripts/harvest-photos.mjs` sweeps it exhaustively — 1,256 candidate files
  across category walks and 90-odd searches. Twenty-one survived automated
  matching; ten survived a human looking at them.
- Openverse can reach Flickr's CC-licensed pool, but filtering by source needs
  an API key, so it is not wired up here.

So 317 of 330 lounges show generic brand art, labelled as such on the page.
**User contributions are the only path that scales** — see "Contributing a
photo" below.

## Generic lounge art

Every other lounge uses generic interior art assigned per brand via
`BRAND_IMAGES`, so all lounges of one brand look alike. **These are not
photographs of the specific rooms** — the UI says so, in the badge on the image
and in the notice under it.

## Contributing a photo

Every lounge page has an "Add a photo" link that opens a pre-filled GitHub
issue (`.github/ISSUE_TEMPLATE/lounge-photo.yml`) with the lounge already
identified, an upload area, and a license choice. To publish a submission:

1. Check the licensing claim is plausible — that the contributor really took
   the photo, and that it shows the lounge named in the issue.
2. Save the image to `assets/lounges/real/<slug>.jpg`.
3. Add an entry to `LOUNGE_PHOTOS` in `scripts/lounge-sources.mjs` with the
   scope, kind, credit, license and source URL.
4. Add a row to the table above.
5. Run:

   ```bash
   node scripts/optimize-images.mjs
   node scripts/generate-lounges.mjs
   ```

The generator fails loudly if a `LOUNGE_PHOTOS` key matches no lounge id, if a
referenced image file is missing, or if any attribution field is blank — so a
typo cannot silently fall back to generic art, and an uncredited photo cannot
ship.

## Finding more candidates

```bash
node scripts/harvest-photos.mjs            # search Commons, write a report
node scripts/harvest-photos.mjs --download # fetch the matches
```

The harvester is deliberately conservative and still wrong often enough that
**every candidate must be looked at before it ships**. On the last run it
confidently matched a ribbon-cutting photo, a portrait of Delta's CEO, a
restroom, a plate of pita and hummus, and a USO tour in Iraq.
